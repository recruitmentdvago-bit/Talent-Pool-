Which vacancies should the bot source?

Tick the ones to search on LinkedIn. The collector on your PC picks this up the next time it starts. Everyone is still scored against every vacancy.

LinkedIn sourcing runs on your own PC

LinkedIn needs a real, visible browser with your login, which a cloud server cannot give it. So the collector - this same program on your PC - sources LinkedIn for the vacancies below and sends every profile here. This portal scores them and the AI agent reads them. You can also add profiles any time in Import.

Direct LinkedIn sourcing

Opens LinkedIn in a visible Chrome window, searches for each open vacancy, reads the profiles in your target city and files them. Slowly, a few at a time, like a person would.

Automated access is against LinkedIn's terms and can get the account restricted. Pacing lowers that risk; it cannot remove it. If LinkedIn shows any warning, the bot stops by itself and pauses for two days.

Pacing & limits

The collector on your PC uses these. It fetches them from here every time it starts, so change them here, save, and the next run follows. Settings changed in the small local app are overwritten.

Smaller numbers are safer. A new routine starts at 10 profiles a day and grows by 5 each active day up to your limit.

Scoring Weights

Adjust how much each dimension matters when scoring candidates. Weights are renormalized to 100%, so the absolute numbers don't need to add up exactly.

Run the agent

After profiles come in (Import, or the LinkedIn collector), the pipeline reads and rubric-scores them. The AI agent then reads the best ones against each vacancy and gives its own score.

Agent settings

Make a list of target companies and say where it applies: whole departments, specific roles, or everything. Every matching vacancy gets those companies automatically. A vacancy with no company list simply searches everyone relevant. Saving rescores everyone.

How the bot uses these lists

Nothing to enter. The bot reads each vacancy's JD and works out which other roles do the same work (e.g. Data Analyst → BI Analyst, Reporting Analyst), then searches those titles too. It re-reads a JD whenever you change it. This page just shows what it decided - edit a rule only if you disagree; edited rules are never overwritten.
